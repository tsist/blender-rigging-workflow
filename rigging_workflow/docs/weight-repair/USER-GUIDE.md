# 局部权重修复套组：人工使用指南

## 0.42.2统一候选说明（2026-11-13）

本指南适用0.42.2统一候选中的原0.42.0区域内核；人工步骤、锁/预算/非目标保护不变。候选生成后仍需同姿态逐骨权重、组和/差值、CTRL→ORG/MCH→DEF及皮肤联合验收；工具通过不代签肩胯。


本指南对应 **0.42.0 本地候选版**，工作树为 `work/rigging-modular-20261112-v001/rigging_workflow`，面向 Blender 5.2.1；尚未替换日常安装。指南本身不表示肩部、胯部或全部模板已经通过视觉验收。实际安装包和最终验收以本批主报告为准。下文 Stage 指“阶段”；面板可见名称为“阶段与操作顺序”“当前计划”和“高级配方编辑”。

## 1. 用途与输入条件

套组把多个局部区域、多个操作和同一骨架的多个独立网格编成配方，一次创建独立候选。原源对象不被修权、替换或删除；骨架和已有动作不作为修权写入目标。

当前支持有真实生成身份、已校准中立姿态的角色，沿用现有绑定核的输入要求。不是任意第三方 Armature 的通用适配器。检查和提交需要对象模式、本地可编辑对象、同一有效骨架；修改器顺序为 Armature 在首，其后只允许受支持的可选 Subsurf。共享 Mesh、额外约束或不支持的动画/修改器结构会被拒绝，不会自动清理后继续。

实际 deform 权重必须有限、每项在 0–1，逐点总和在 1±1e-5。套组不会为使输入通过而全局归一。Rig 可以保留已有动作，但修权准备时必须符合已校准中立要求。Key 仅支持现有核明确允许的有限结构，不能据此推断任意 Shape Key 动画或驱动都可使用。

## 2. 第一次操作

1. 在 3D 视图按 **N → 角色工作台 → 绑定与蒙皮**，展开 **09 · 局部权重修复套组**。如插件尚未注册，本指南不会使该面板自动出现。
2. 选择源网格和骨架，为网格填写明确的逻辑 key，如 `body`，点击“登记/更新目标逻辑key”。多网格逐项登记；同一对象不能以两个 key 重复登记。逻辑 key 是配方引用，不等于自动按对象名寻找目标。
3. 捕获区域：可先在编辑模式选择真实 RAW 顶点，再用“当前可见RAW选点”捕获；也可选择遮罩组，捕获全部正权重点。两种来源不叠加。填写区域名，点击“捕获并保存区域binding”。
4. 用区域列表的“写域”“读域”查看实际点集。这些按钮只改变选择状态。捕获完成后退出编辑/姿态模式，回到对象模式。
5. 在“操作编辑器”选择区域、操作类型和可写骨组。普通数值、倍率与映射使用表单即可，无需手写 JSON。点击“加入阶段（默认新建）”。
6. 点击“检查并准备”。阅读锁、零质量、区域冲突、质量残差/预算、实际变化点数和差值报告。检查成功只是准备好内存计划，此时没有候选。
7. 点击“预览范围”检查独立范围显示副本。范围预览不等于修后变形预览。
8. 点击“创建候选”。一次成功会为本计划的各目标创建独立候选，清理本次范围预览。原源仍保留；候选名称和报告显示在面板中。
9. 保存独立工作文件，并在相同姿态下比较原源和候选。自动多姿态图请走第 8 节的隔离诊断，不能在操作现场自动改姿态冒充保护完成。

修改区域、参数、映射、Stage、源权重、锁、骨架、帧或单位后，需要重新检查。一个计划只允许成功提交一次；重新检查会建立新计划。

## 3. 选择哪种操作

| 操作 | 适用场景 | 必须明确的内容 |
|---|---|---|
| ASSIGN 精确赋值 | 指定某些骨的最终权值 | 骨组及数值；剩余质量由显式 remainder 组承担 |
| TRANSFER_AMOUNT 定量转移 | 从指定骨让渡给另一骨 | 源组、接收组、固定量或源权比例 |
| REBALANCE 比例重平衡 | 保留现有支持范围，调整多骨比例 | 每个可写组的非负倍率 |
| SMOOTH 邻接平滑 | 缓和局部突变 | 读域、屏障、1–100 次明确迭代 |
| SURFACE_TRANSFER 表面转移 | 从已有供体建立局部提案 | 供体、距离上限（米）、完整骨组映射 |
| MIRROR 镜像 | 已核对的左右对称区域 | 先构建并确认点对，再填骨组映射和模式 |
| FIELD 显式场 | 高级逐点提案 | 与区域点数、可写组数一致的非负数组 |

ASSIGN 的 `values` 和 `remainder` 必须互斥，合起来覆盖全部可写组。完整赋值不偷偷缩放；正余量而 remainder 原权重总和为零时会拒绝。表单标量行可写 `骨名=0.2`；高级逐点 JSON 填入后会优先于标量行，避免遗留高级数据覆盖本次意图。

TRANSFER_AMOUNT 的固定量不能超过该点源组现有质量；比例为 0–1。超预算整步拒绝，不自动截到最大值。REBALANCE 必须为全部可写组提供倍率；不能把正质量全部乘成零。

## 4. 区域、独立预算和 Stage

每一步只在明确的可写骨组集合内重新分配该点本步原有质量 M。例如某点这两组原值为 0.3 与 0.2，则本步预算是 0.5，其它组不会替它吸收误差。M=0 的点默认保持零；若要引入权重，必须把真实供体组纳入集合。alpha=0 的点保持原值和原 membership。请求包含任一锁组会拒绝整个操作，不会自动过滤锁组。

区域中的 `ids` 是候选写域，正 alpha 才是实际写点；`read_ids` 可比写域大，供 Smooth 读取邻接数据。扩圈沿 RAW 真实边进行，种子 alpha=1，距离为 d 的扩圈层 alpha=1−d/(rings+1)；读域还可包含允许的外一圈。遮罩捕获在 rings=0 时使用实际遮罩权值作 alpha；开启扩圈后按扩圈规则生成 alpha。屏障必须是真实 RAW 边，阻止扩圈/平滑跨该边，不会自动推断腋下或胯部解剖边界。

同一个 Stage 内，各操作读取同一份冻结输入。同一目标任何正 alpha 写点重叠都会拒绝，**即使操作写的是不同骨组**。需要先后影响同一点时，把操作拆成不同具名 Stage；后 Stage 消费前 Stage 的 float32 结果。不同目标的区域可同处一个 Stage。

表单默认每次新增独立 Stage。只有确认写域独立时，才填现有 Stage 的 1..N 编号合并。在“阶段与操作顺序”可上移、下移、重命名或点击“删除阶段”，也可“载入”某操作后编辑并“更新所选操作”。调整顺序会改变结果，需要重新检查。复杂逐点数值可通过配方导入，“高级配方编辑”不是普通操作的必经入口。

## 5. 镜像与表面转移

镜像流程：捕获左、右区域及可选中心区域 → 在区域列表设置对应点域 → 填轴、平面和米制容差 → “构建配对” → 阅读未配/歧义/最大误差并“预览线段” → “确认当前配对” → 添加 MIRROR 操作。未配或歧义不能靠确认按钮强行通过。

COPY 固定左→右，写域必须来自实际配对右侧。AVERAGE 可写两侧，骨组映射必须双向对合，例如 A→B、B→A；保持各点自己的本步预算。中心自配的 COPY 仅允许骨组自映射，互换组应显式选择 AVERAGE。供侧所有相关正权骨列必须完整映射；几何近邻不证明语义正确，仍需人工核对。改坐标、拓扑、变换或单位会使旧配对失效。

表面转移选择同 rig、符合供体要求的独立网格；**同计划任一写入 target 都不能作供体**。如要用上一轮候选作供体，先结束上一计划，再把它作为后续新计划的外部供体。距离上限单位始终是米。映射使用每行 `源骨组=目标骨组`，目标列唯一，覆盖供体实际正权列及全部可写组。供体区域索引可选，参与求交的是满足约束的完整 RAW 三角；有未覆盖点或距离超限时拒绝，不会模糊回退。转移结果仍只重新分配目标可写组的原预算，不等于直接覆盖全部权重。

## 6. 配方保存、加载和批次

“保存配方”选择全新 JSON 路径，不覆盖已有文件；目标目录须已存在。UI 保存配方会结束当前计划。“加载配方”后仍需显式登记目标映射，再检查。保存 .blend、加载文件或卸载插件同样结束当前计划；磁盘文件不会恢复旧提交权。

配方保存区域 RAW 点号、alpha、读域、屏障、对象绑定和有序操作，不能直接移植到不同拓扑。同输入对象改名或明确映射到等价对象时，可使用“同输入显式重绑定全部区域”；坐标、拓扑、变换、组、rig 或单位不符时必须重新捕获。镜像仍须满足其独立配对绑定检查。

单计划支持同 rig 的多个独立 Mesh，成功时整体创建候选；创建中失败会撤回本次未完成候选。若报告 `rollback_incomplete`，须检查清理错误，不能视为已恢复。跨角色批次通过公共 Python `run_batch` 逐项执行，当前面板没有单独的批次按钮：默认首项失败停止，显式选继续才处理后续；已成功角色保留，不是整批原子事务。取消在角色间生效，不承诺打断一个同步算子。

## 7. 取消与回退

“取消计划”清理本计划范围预览，不删除已创建候选；“结束本Scene UI会话”结束该会话、清其配对及 owned 预览，保留区域/配方/Stage和已创建候选。收起面板不是取消动作。预览和候选都可能与原源重叠，判断前请明确当前观察对象。

候选不满意时继续使用原源即可。工具不自动替换角色、迁移动画或删除任何生产对象；接纳候选后的工程替换、结构修改和动画转移应单独安排，不能承诺任意动画无损迁移。不要把上轮候选不加辨别地当作下一轮原始基线。

## 8. 隔离诊断与首组观察门

自动采姿由 `weight_repair_diagnostics.compare` 在**独立后台 Blender 工作副本**执行；当前普通面板没有自动采姿按钮。不得为自动诊断直接改变用户现场的姿态、帧、动作、相机或显示设置。调用示例见同目录 `AI-CALLS.md`。

诊断顺序：

1. SURVEY 仅生成相机投影和可见性调查，不出图。ROI 至少三个真实 RAW 点；最好包含完整病灶三角及必要外环。可见性是完整 ROI 三角的离散重心射线采样，不是全部表面可见的证明；没有完整三角时更不能据此判定可见。
2. FIRST 只渲染首姿态、首视角组及骨架总览；需查看实际皮肤前后、RAW、相关各骨权重、组和、差值和 CONTROL/MECHANISM/DEFORM 骨层。核对观察域入框、尺度、遮挡、近裁切和完整相关骨链。返回 `first_group_pending_review` 表示等待审阅，不能自动解读为通过。
3. 实际看过并接纳首组后，FULL 才使用同输入的 gate 与首组回执继续；复用时还核首组图像哈希。输入、相机、姿态等改变需重建 FIRST。遮挡视角可能跳过，查看 `skipped_views` 和 `visibility-check.json`，不要把跳过当作通过。

输出包括 PNG、逐点全组 CSV、求值点/权重 NPZ、骨层/driver JSON、可见性检查和 receipt。权重色阶固定 0–1，零为黑；delta 使用显式范围、红为正、蓝为负、白为零。组和仅表示所列相关组，不等于自动证明全 deform 总和。FULL 的 `captured_pending_visual_review` 也只是采集完待视觉审核。

## 9. Scene 与高级脚本限制

切换 Scene、保存/加载和卸载会结束受支持入口中的计划，回原 Scene 不能恢复已失权计划。脚本、AI 或 CLI 在任何程序化 Scene 切换前，**必须调用 `invalidate_scene_context()`**，切换后重新准备；CLI 每个工作单元只处理一个 Scene。

第三方直接 RNA 同步 A→B→A，未通知且最终状态完全恢复的历史不能可靠观测。不能宣称工具自动检测一切瞬时 Scene 往返。当前实际源状态检查仍严格执行，这项边界不授权跳过失权入口。

## 10. 本指南的验证口径

文档逐项对应当前源码、API-CONTRACT 和 Scene 生命周期修订；本次文档分片只做静态接口核对，没有新增 Blender 运行或视觉验证。检查成功、候选创建、精确回读与视觉质量是不同结果。尚未完成的肩胯修复、完整 GUI 覆盖和性能泛化，不因这些操作说明而自动成立。
