# 人形动画重定向：0.40.0 工作台

本版将原“动画重定向”侧栏收进统一的“角色工作台”→“动画重定向”阶段。先选角色并点击“进入角色”，再选择 FBX / BVH、MMD 或通用映射来源。日常显示主要转换和正式使用；“进阶”展开后台队列、普通FK目标、接触检查与可选镜头；“开发”显示详细审查。后文旧面板名称对应这些阶段内的分区。

Profile长动作：先在通用映射面板明确来源、目标并加载/校验Profile；进阶队列选择“Profile → C94”，点击“从Profile面板填入”，核对队列来源、目标和后台工作目录。可添加多个同源Action，逐条指定Slot、时基和范围后提交；用结果序号选择条目，成功结果单独收集、预览，停止后恢复原动作，任务终态后释放。普通FK队列使用已确认target_policy，流程共用同一组状态和取消入口。

旧相机Profile需要升级时，使用进阶“可选MMD镜头”的显式迁移入口，提供原JSON/原库及预期SHA，选择不存在的新sidecar路径。迁移保留旧文件，不自动追加相机或设为活动；完成后再读取新Profile。不要手改旧签名放行。

本包面向 Windows / Blender 5.2.1 LTS，采用 legacy add-on ZIP 安装。本技能配套0.40.0-r3公开预发布，安装由用户显式操作，不自动更改已有配置。源文件、原角色动作和新候选分别保留；先在工作副本中预览，再明确选择持久绑定或NLA。具名支持范围见随包 `SUPPORT-MATRIX.md`。

## 安装、入口与回退

1. 保存当前工作。打开 Edit → Preferences → Add-ons，右上菜单选择 Install from Disk，选择交付的完整 `rigging_workflow-0.40.0-local-*.zip`，启用“角色绑定工作台”。这是 legacy 包，不使用 Extensions 仓库安装；不用另装一个同名包或把ZIP中的目录再套一层。首次先在独立配置中试用。
2. 在3D视图按N，打开“角色工作台”，进入“动画重定向”阶段。来源与显示层级决定可见分区；首次只用工程工作副本，注册成功不代表任意角色转换已通过。
3. 旧版已启用时先保存文件并禁用旧版，保留旧ZIP。更新会换插件代码，不自动重做既有Action、rest或约束。
4. 回退时先保存需保留的候选/报告，禁用并移除本包，再从原ZIP安装旧版。卸载插件不删除工程中的独立Action/Text。生产修正、下载依赖和改全局设置均由独立明确操作决定。

基础重定向与已有来源Action播放不需要MMD Tools。只有MMD文件/镜头后台导入需要下文外部依赖；缺依赖时报告原因，不自动下载或安装。

## 检查骨骼动作

以实际骨骼动作的自然性、连贯性和动作意图判断效果，不要求逐骨角度或端点精确重合。显示完整躯干、四肢扭转分段和五指；隐藏必要骨段可能造成断链假象。头部和手掌应结合局部轴检查完整朝向。

重定向动作按骨骼与控制链判断，网格变形及权重须另外复核。完整旋转残差和 `bone_direction_residual` 用于诊断，不是逐项不劣门。原生限位、约束、rest、源与旧Action保持；额外动作或接触修正仍须逐问题确认。

Blender5.2.1中，`Bone.hide`作用于编辑模式，`PoseBone.hide`作用于其它模式。原项目分别观察过真实视口预览与骨骼数据示意，不能混作同一种视觉证据；公开范围见随包[验收摘要](VALIDATION.md)。编码24fps不代表视口实时24fps。

## 导入与生成基础候选

MMD：在“动画重定向”侧栏的MMD文件入口选择VMD；首次可用随包Uka骨架参考，也可填写自有PMX及明确资源路径。后台导入成功后收集来源，为身体、已有表情/口型和眼控选择同一片段ID，检查来源Profile与映射，再选择目标骨架。保留移动和原地模式均支持，默认保留移动/转向。预览后“停止并恢复”回原工作状态。

Mixamo、BVH及场景已有动画：选真实来源骨架和Action/Slot，核时基与映射；未知来源可用纯JSON Profile。没有可信Action时基时明确填写源fps。来源Action时基与Scene保存fps分开；按秒映射，不把二者混为一项。

非预设FBX/BVH：在“通用来源重定向Profile”点击“导入通用FBX / BVH”；BVH明确源轴和每单位比例。导入不因骨名陌生而失败，也不猜语义。加载已有Profile，或填写“语义映射JSON”后指定新JSON路径→导出→校验→选择帧域与采样步长→生成候选。单文件当前要求一根来源骨架；多骨架文件在场景中显式选择。自动映射只是建议，`configured`不冒充已验预设。同步Profile候选可在正式使用面板选择“通用Profile”；长动作改用通用后台队列。

长转换使用后台队列。每项独立成功/失败，收集只增加候选，不自动替换当前动作。后台MMD结果预览后，在MMD面板的“候选Action”字段明确选择准备正式使用的结果；正式使用前再核一次所选名称。

当前已验代表来源包含Mixamo Samba、CMU跑跳和MMD舞蹈。预设名不等于任意同类素材都已验；Profile当前输出到C94，Mixamo/CMU另有显式普通FK目标。未知约束/驱动图不冒充普通FK。Profile采选定Action/Slot并隔离NLA，不合成已有NLA轨。

MMD新导入来源将已识别IK开关编译为原生台阶曲线；未知动态通道拒绝，未知静态通道明确报告未消费。旧来源无相应证明时需重新导入。表情/口型与眼控只匹配已有目标控制，缺项报告，不自动新造表情；当前骨骼眼控机制与眼球皮肤效果分别判断。镜头单独显式追加，设为活动/恢复均不覆盖用户后续选择。

## 可选头颈分担

身体或MMD面板选择目标和已有生成候选，点击“生成头颈分担预览”。它另建Action，保留原候选，仅重建头颈七旋转通道，保原生限位和跟随；不重新导入源素材。“停止并恢复”回预览前状态。未选候选时使用目标当前绑定的生成Action。

按真实骨骼视觉决定是否使用；MMD当前基线不因数值偏差自动要求分担。候选保留历史报告，旧残差不是新测量或质量批准。

## 正式使用与撤回

1. 在“正式使用基础候选”面板选择“候选来源”：身体/通用、MMD或通用Profile。它读取对应面板的目标和候选，界面显示将使用的实际名称，不覆盖另一面板选择。
2. 先停止临时预览，选择“持久绑定Action”或“追加NLA”，核对目标、候选与使用方式，再勾选“我已检查此基础候选和已知限制”。切换来源或使用方式会清除复核；目标、候选或记录改变后须重新复核。
3. 点击“正式使用已复核基础候选”。Action模式遇到正在求值的旧NLA时，须明确隔离；NLA模式要求先明确静音/隔离旧未静音或独奏轨道，不自动改旧轨。
4. 保存工作副本后保持正式绑定；“检查绑定回执”可查看记录。“撤回并恢复原状态”只在本入口仍拥有相关状态时恢复旧Action/Slot、输入及动态开关，候选保留；用户后改相关状态则拒绝覆盖并保恢复回执。

MMD与身体候选共用同一正式使用核。快速稀疏预览、未知记录和接触修正候选不能借此入口正式使用。复核勾选不从文件恢复，也不能替代逐问题修正确认。原辅助动态保留并暂关；需要匹配新基础动作时另行重捕获，不自动重烘焙。

重捕获时先停止动态RAM预览，确认新基础Action已明确绑定，在原发裙/胸臀动态专项面板选回原分组、帧域与参数，执行捕获→动态预览→需要时另存独立烘焙。对应API入口为 `surface_dynamic.capture(rig, group, ...)` 或 `elastic.capture(rig, ...)`；完整参数沿各专项既有合同，不把 `retarget_dynamic.capture` 状态快照函数当成模拟重烘焙。旧动态输出保留，是否替换须在专项路径明确选择。

## 足底报告与额外修正

基础转换后保留既有自动只读检测编排。表面模式需完整显式Mesh/足底片区/地面/时基校准；缺校准报告 `needs_calibration`，普通FK报告 `not_supported`，基础骨骼候选仍保留。骨骼动作验收不要求先处理网格或权重。

只检查骨骼时，可用校准JSON顶层 `measurement_mode='bone_anchors'`，source/target各声明 `rig`、`coverage_status='explicit_declared_anchors'`及每侧heel/ball/toe三个独立骨局部标记。每个标记含唯一anchor_id、实际形变骨bone、local_offset[3]、units='bone_local_scene_units'、semantic和非空校准basis；另明确参考plane、帧秒表、尺度、根运动与对齐。该模式完全不采Mesh/权重，报告覆盖 `declared_bone_anchors`，皮肤及完整足底始终未验。人为骨骼参考平面要如实标注，不能把Z0、最低点或骨尾称作真实地面/皮肤。

两种测量模式的校准身份和问题不能混用；缺完整前足不签生产贴地。骨锚点检测还绑定原Object未动画输入与父空间；移动/旋转/缩放目标后须重新检测，旧缺该身份的骨报告也须重做。按所选Action排除动画分量，不能把切换动画帧本身当成外部变更。复用原只读采样/局部求解/逐问题确认核，骨锚点也要保护另一脚及本脚其他标记。运行采样是有限时刻，不等于连续无滑移或完整视觉通过。

问题报告可保存为Text，但报告没有批准权。精确报告/问题ID/原Action与校准一致后才能传入专项修正；额外修正仍独立预览、逐问题确认。手与身体接触不在当前自动修正范围。

“手与身体·人工复核提示”提供有限的观察记录路径：明确候选、两根骨名、目标帧域、观察描述与来源后，记录为新Text。校验会核对角色/Action-Slot/曲线/rest身份，变化后显示stale并保留原文；保存重开及撤销/重做后须重新校验。它不做自动碰撞识别，fresh只表示记录仍对应当前候选，不认定碰撞、不能批准修正，也不能传成足部问题。自动报告中的手/身体 `not_analyzed` 保持准确。

## 后台规模与性能

已实测同一真实Samba来源的20个不同短窗口，一次队列20成功并全部收集；每项7目标样本。此为规模夹具，不能称20个不同动作库。该次CLI同步快照/提交约18.8秒、worker约349秒、收集约11.1秒，观测工作集峰值约1.36GiB。同步快照阶段会占用宿主时间；此组未做新的GUI响应观察，交互与取消沿用既有原生GUI长作业证据。无实时性能承诺，64条输入上限不等于64满载实测。

已有真实60秒MMD片段1441目标样本通过公共后台转换，旧实测约1361秒。优先短片/稀疏快速预览，正式完整转换交后台。取消需等待终态，成功项可保留收集；取消调用返回不等于worker立即退出。任务完成后释放本任务闲置Blender实例，不结束别人的作业或丢弃未保存窗口。

## Agent/API与运行依赖

基础转换使用已有 `retarget_action` / `retarget_mmd` /来源队列共核。与GUI相同的自动检测编排使用 `retarget_pipeline.complete_detection(...)`，缺校准时保留明确待校准状态。头颈使用 `retarget_headneck.rebalance_action(rig, action=...)` 返回独立Action/Slot，不自动应用；显式帧须覆盖原完整首末域，短段先建立独立clip。

明确复核后，`retarget_publish.commit(target, action, slot=..., mode='ACTION'或'NLA', reviewed=True, ...)` 持久使用，`withdraw(target)`撤回。API的 `reviewed=True` 是调用者的明确决定，不从报告或检测结果推断。额外接触修正使用其专项核。

已验环境：Windows、Blender5.2.1 LTS、blenderctl0.85.0。MMD文件/镜头后台导入另需已装MMD Tools4.5.14、OpenCC0.1.7 wheel及PowerShell7；ZIP不带这些运行时，也不自动安装。迁移时填写真实路径。已有原生来源Action播放不要求当前GUI启用MMD Tools。

文件后台入口需填写本机 `blenderctl.ps1`、MMD Tools目录和OpenCC wheel路径；默认F盘路径只是本项目机配置，换机要修改。镜头后端还核具体文件hash，随包 `MMD-BACKEND-IDENTITY.json` 列出精确已验身份，同版本不同构建也可能被拒绝。镜头当前为人工轨道/机制夹具级验证，未覆盖真实带镜头轨的VMD及原MMD播放器逐帧视觉对照。源NLA合成尚未实现，当前只隔离并采选定Action/Slot；输出NLA追加是另一项已支持功能。

此安装包的动画入口不依赖开发树路径；历史GLB交换UI未注册、交换worker与其开发路径限制属于独立API边界，不属于本次动画重定向交付范围。

包内保留THIRD_PARTY_NOTICES与Uka许可/来源sidecar。标准Uka未改PMX只作骨架/IK参考，不带贴图；自有PMX/VMD许可分别核对。本机有限运行与视觉观察不等于任意角色、连续接触或完整作品质量认证。
