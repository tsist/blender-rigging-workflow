# 独立人形与四足模板使用说明

## 0.42.2统一候选说明（2026-11-13）

生成时的中立接受依据为每个变形骨原15个rest点按实际B-Bone段选择/混合后的误差；完整joint baseline、签名与当前姿态检查仍保留，旧record直接可读，不需要重签。它是有限采样，不能当整皮/连续空间保证；已有姿态应恢复生成中立，不要把有姿态的骨架重新capture成baseline。A样本435实际采样点与1155 joint×probe组合是不同计数。

“使用动作片段”默认关闭；开启后起止填写来源帧，可含小数。关闭按原完整范围传None。选段生成新Action，源Action/时基保持。REST朝向独立于片段第一帧，CLIP_START按本次选段起点采样。GUI未新增output_start字段；四足仍只手工动画。



## 本批低模与局部检查约定

本批Tripo样本采用Tripo云端重拓扑低模；原高模保留作来源和外形对照，既有高模实证保持各自范围，不代签低模。生产检查先继承已保存的普通蒙皮权重，明确记录TRANSFER；不在本地重拓扑，不反复全身重算。

肩胯问题须在相同视角和0–1色阶下并排比较相关各变形骨及辅助骨的权重，结合相关组总和、选点权重表与骨架视图，沿控制输入→ORG/MCH→最终变形骨/helper定位。按实际use_deform和消费关系判断骨职责，不能只看名称、最终几何或旋转角度幅值。先固定一层原因，再对明确点域/组做局部修复并复验；保留原候选和回退。

多Object身体的代理回写增加几何来源过滤：只保留当前来源三个顶点均归属且有体素支持的完整三角；任何生产点无完整有界覆盖时拒绝整个候选，不自动扩大距离。该方法是顶点几何近似，不能消歧完全同位置重叠，也不证明三角内部语义归属。


当前代码候选版本为0.41.0，尚未替换日常安装或公开发布。以下017/018/019/020等编号是本次开发证据快照，保留各自实测范围，不是需要依次安装的版本；最新范围见本说明末尾的当前验证边界及本批审计报告。

本说明针对模块化开发候选。它与旧C94角色流程并存：新模板由Blender自带Rigify组件生成，不依赖私有C94角色、定位图谱或模板文件；旧C94工程继续使用原路径。模板生成、定位、蒙皮和动作候选是不同阶段，各阶段都需要检查实际结果。

已有真实Tripo人形722,809点和真实犬716,030点的017技术直绑证据，原生产点全部覆盖并核对原几何／UV保持；018接纳retarget两模块及UI接线，之后补齐模板/部分组合、原生四足IK及可见人工链/保存冷开。当前可选原生平滑能改善局部细碎硬折，宏观肩窝凹陷与大角度挤压仍需检查，不宣称主权重串扰本身已全部解决；详见本轮验收。旧015四姿态不代签017全流程，自动骨位与人工复核骨位分别记录。泛型文件的新目标仍为有限证据，不把具名来源通过推广到任意骨架。

## 安装与工作副本

使用同版插件安装包及其安装说明（本说明是文档候选，不表示已安装或已发布）。在目标Blender中启用“角色绑定工作台”，按N打开同名侧栏。先把角色工程另存为自己的工作副本，保留原模型与旧绑定。

参考创建和正式骨架生成需要当前Blender中可用的Rigify；目标环境核对的是Rigify 0.6.10及Blender 5.2.1。新工作台会在需要时尝试仅为当前进程启用Blender已有的Rigify，不安装或下载它，也不保存用户偏好。缺少组件或出现半注册错误时，保留工作文件，用全新Blender进程核对依赖；不要逐个补参数或反复覆盖安装。

已有角色选择明确骨架并点击“进入角色”。新角色从“准备与定位”中的“独立人形与四足模板”开始。模块化流程不需要选择旧C94的私有模板库。

## 1. 选择基础模板与模块

选择“极简人形”或“猫狗类四足”，填写新角色名称，选定原始模型，再设置本次组合。

| 模块 | 首版含义 |
| --- | --- |
| 身体 | 必需的躯干、重心及基本控制。 |
| 颈头 | 颈部与整体头部，不包含眼球、下颌或表情控制。 |
| 左／右臂或前肢 | 人形整掌手臂，或四足前爪机制；没有精细手指控制。 |
| 左／右腿或后肢 | 人形腿与必要足部控制，或四足后爪机制。 |
| 尾巴 | 可选分段尾巴；首版不包含尾巴物理或触手功能。 |
| 肩胯辅助修正骨 | 可选局部形变辅助骨，按当前组合中实际存在的关节安装。 |

点击“创建独立参考骨”产生新参考。改变勾选项不会直接改造已生成角色；对已有参考使用“按模块创建新参考候选”。新候选保留共用骨段的当前编辑，原参考与旧角色保留。

## 2. 自动提议、手调与确认

1. 明确模型正面和Z向上，点击“自动提议关节位置”。面板支持`-Y/+Y/-X/+X`；已核对`-Y/+Y`，并对真实人形±X、犬±Y有定位分片的代表证据（主包018未重跑定位）。其他方向或模型仍须实际检查，不能把某个方向当成通用保证。
2. 从正面、侧面及斜视检查骨盆、躯干、肩肘、腕部、髋膝和脚掌；四足还要检查前后肢的不同关节结构及后膝／飞节。自动结果始终只是待检查候选。
3. 点击“手调参考骨”，在编辑模式调整骨头／骨尾及必要的骨轴。工作台开启参考的X镜像编辑；镜像针对参考局部X和成对的`.L/.R`骨，不等同于任意世界方向的自动对称。不要通过改名、增删骨或改父级来代替模块组合。
4. 调整完成后退出编辑模式，点击“检查完成，确认参考骨”。再点击“生成新角色骨架”。

如果模型、参考变换或配置改变，旧确认可能过期。按提示重新检查、提议或确认；不要手改签名或把“未估计”当成已手调。自动定位不读取旧骨架或旧权重作为识别答案。

穿衣人形尤其要核对髋头是否落在实际关节高度。当前Tripo样本中，旧017人工复核版把双髋从自动提议处下移约7.7厘米，膝位不变；中立叠图支持继续保留这份人工复核输入。新自动候选仍需检查，不能因27/27骨段都有候选或绑定成功就直接认定骨位合适，也不把两套骨位的变形差异归因于求解器。

多个Mesh组成身体时，可指定“分件身体集合（可选）”；定位会读取该集合及其子集合中的全部Mesh。当前“原始模型”必须属于这个集合。集合只放身体的生产源分件，服装、薄片和刚性附件另按第5节处理，已经生成的候选也不要加入身体来源集合。改变集合成员后重新提议并检查参考。

## 3. 生成后的控制与检查

生成操作创建新角色骨架，保留参考与旧角色；新参考或新rig会清空工作台里的旧蒙皮／动作候选关联，旧对象和Action本身仍保留。进入“角色控制”，点击“进入骨架姿态模式”，选择原生控件调整全局、重心、躯干、头颈和四肢；尾巴按段调整。

IK/FK滑块沿用原生Rigify定义：0为IK，1为FK。直接改滑块会改变求值姿态；不要把它当成已验证的保姿态匹配或自动补关键帧。按Blender正常方法为明确控件和属性打关键帧。

辅助修正骨承担局部形变分担，不是面部控制或手工Shape Key修正。只有在生成配置中启用它们，新rig才有对应骨与局部分配规则；单纯改变面板勾选不会给已有rig补骨。检查抬臂、抬腿及胯部过渡，不能只看辅助骨角度或权重非零就认定变形良好。

人工GUI中旧骨架、旧蒙皮候选或旧显示可能遮挡新骨架。此时不要删除旧对象：暂时隐藏旧对象的视口显示（眼睛图标或H），让原始模型保持中立静止并显示，再检查新骨架与候选；检查后恢复旧显示。工作台保留旧对象和Action，不用删除或覆盖工程来“清场”。

020起内部计算代理默认隐藏，仍保留在工程中供需要时检查；创建蒙皮候选后“当前角色”保持指向它的生成骨架。019已通过可见界面的创建参考、自动提议、手调入口、确认、生成、后台求解、创建候选及进入POSE链；保存后在独立进程、不导入制作插件的条件下核对了722,809点原坐标/拓扑/UV、全部权重、89个driver和原生root编辑。020两项显示修正在16,026点夹具上通过同一实际求解/应用入口。此项是流程与数据验证，肩胯视觉仍另判。

## 4. 单Mesh原始模型体素绑定

在“绑定与蒙皮”的“原始模型体素绑定”中，选择原始Mesh和本次生成骨架，填写作业目录或先保存工作副本。

当前主体入口要求明确的中立新输入：本地Mesh、无旧顶点组、形态键、父级、约束或动画，修改器仅接受原有Subsurf。若输入不符合要求，先保留原件并建立清楚的新输入；不要删除原工程的数据来绕过拒绝。

| 计算代理 | 作用 |
| --- | --- |
| 自动检查闭体 | 原表面可定义闭合计算体积时用其副本；否则尝试内部体素代理。 |
| 原表面副本 | 要求原始表面可定义闭合体积，不能时明确拒绝。 |
| 内部体素代理 | 只重建计算用副本，再对原始生产顶点求权重；原模型拓扑、UV和外观保留。 |

设置最长边格数后点击“开始后台体素蒙皮”。提高格数会增加计算和内存，并不保证细小间隙或全部输入自动成功。新入口默认使用26邻接加权体积图，仍阻断穿过表面的邻接，不能理解为允许权重穿面扩散。后台提供状态与取消；成功后仍须点击“创建独立蒙皮候选”。原模型保持，结果是独立候选。

实际计算保留代理的完整体积，先识别哪些代理表面点有明确体素场支撑，再仅使用三个顶点都获得支撑的完整三角作回写供体。没有支撑的代理点只从回写供体中排除，不会从代理体积中删除，也不会删除生产点。

“代理回写距离（格）”默认3，可明确设置为0.5–4格；它按当前体素格大小换算成实际距离，把体素场通过表面重心插值回写原生产点，需要时最后分配局部辅助骨权重。真实人形样本明确选择了3.5格，该值没有变成默认，也不是遇到失败后自动扩大。报告分别记录体素求解、`barycentric_volume_field_transfer`回写及辅助骨分配。全部原始生产点必须在明确距离内有合法结果；超距或无法覆盖时拒绝应用，不自动扩大距离，也不用最近骨权重兜底。

辅助骨不会作为额外全局体积源与主骨竞争；启用时使用有界的局部主骨权重分配。失败或取消不应应用不完整权重。看到成功状态后，仍需检查原模型轮廓、中立是否跳变、腋下／胯部粘连和实际姿态。

内部体素代理可能闭合窄缝。当前候选不再删除重建产生的微小碎壳，而是保留完整计算体积并明确记录表面支撑范围。作业中的`field-support.json`记录可用／不可用代理点、输入身份及距离边界；`transfer-projection.npz`分别保存采样顺序中的顶点ID、完整代理RAW顶点ID及两者映射，并保留实际重心系数和距离。投影记录明确标为“仅投影、不是提交回执”，其存在不代表候选已创建成功。生产原始点仍全部保留；若原始几何本身贴连、缺失或不适用，报告清楚原因，不把大幅手工重建后的结果当成原始模型直接绑定成功。

## 4A. 多个独立Mesh组成身体

新面板可通过“分件身体集合”声明完整身体。单一Mesh不需要集合。该候选接口保留每件的生产拓扑和UV，只把几何组合成内部计算代理。

1. 把无绑定、中立的身体源分件放入一个明确集合；检查其子集合没有混入服装、附件、求解代理或已有候选。
2. 选择集合及其中一件作为“原始模型”，用全部身体表面提议并确认参考，生成同一rig。
3. 在绑定阶段保持完整身体集合，逐件选择当前要绑定的原始模型。每件分别点击开始求解、等待成功、创建独立候选，再检查该件与接缝。
4. 处理下一件时继续使用相同的完整身体来源。各任务会冻结并核对这些来源；改变任意来源后，旧结果需要重新准备。

每件都是独立任务和独立候选，**不是一个全部同时提交／同时回滚的批事务**。前一件成功不代表其余分件已完成；某件失败不会自动撤回已完成的其他候选。已有两组partial技术夹具及分件身体代表证据，但不是全部模块排列；不能以单Mesh结果代签完整分件身体质量。

## 4B. 可选原生姿态修正平滑（仅人形）

在绑定成功后、制作动画前，从记录的中立姿态进入“角色工作台→简洁身体控制”，在“人形可选：原生姿态修正平滑”中确认“固定开放边界”保持勾选（`surface_pin_boundary`默认True），点击“创建原生平滑候选”。界面按钮与core同核；`modular_surface.create_candidate`要求显式传入`pin_boundary=True/False`，人工入口默认True，首版只接纳`HUMAN`。

输出是新的Mesh副本，原对象、原蒙皮和全部RAW权重保留；修改器顺序为Armature→“原生姿态修正平滑”（`CORRECTIVE_SMOOTH`）→原有Subsurf。固定配方为factor 0.5、5次、scale 1、SIMPLE、中立BIND，无顶点组遮罩；不扫参数、不重拓扑、不改权重。创建后一次只显示原蒙皮或新候选其中一个，比较中立、抬臂、左右抬腿、外展及蹲姿。

现有证据：16,026点partial夹具核心9项、UI操作符11项通过；真实722,809点C017绑定皮肤经产品UI创建后，neutral最大修正`9.07e-8 m`，left_hip45 `2.01 mm`、shoulder60 `2.93 mm`，关闭修改器三姿态逐点回到原蒙皮，89 drivers、源/rig状态与输入未变。它只平滑微折，默认对照p99仅改善0.7%–2.7%，不能修复原权重串扰、宏观肩窝/髋部凹陷或穿透；pin分支虽把新增接缝间隙归零，髋部高尾仍变差，微三角normal flip仍在。数值与关闭恢复不等于视觉批准。

首版仅对人形提供该配方。犬同一pin=True配方相对默认001在shoulder60的高尾max从3.391升到5.245，产品入口明确拒绝四足；四足继续保留普通体素蒙皮，不把人形收益外推，也未继续扫参。

回退：在新候选的修改器中关闭“原生姿态修正平滑”，即可回到保留的原权重求值；也可直接回到原蒙皮对象。不要应用该修改器，或把平滑候选当作新的绑定供体；后续权重转移/重算仍使用保留的普通原蒙皮。

## 5. 服装、薄片与刚性附件的手动接续

身体候选完成后，在工作台选择同一新骨架并点击“进入角色”，切到“绑定与蒙皮→进阶→05·权重策略”。此处与AI使用同一`skinning_policy`核心。

### 服装或薄片：TRANSFER

选择需要绑定的新目标Mesh、同一生成骨架，以及**已经应用权重的身体候选**作为供体；选择权重转移方法并明确最大转移距离。准备计划、查看范围／方法，再创建独立候选。

该操作读取供体实际RAW顶点权重，按表面场转移，方法会标为转移；它不是对服装重新完成了一次体素求解。供体须处于同一rig的中立状态，目标和供体不能是同一对象。远离供体的薄片、独立发束或不合身服装不保证适用；先选择合理供体／明确区域，再看实际动作，不扩大距离来掩盖错误来源。

### 刚性附件：RIGID

选择目标Mesh、同一生成骨架和一个明确的最终形变骨，再准备、应用计划。整目标将刚性跟随该骨。骨选择器可能显示所有骨，但控制／机制骨不会通过核心校验；从新rig的最终`DEF-*`形变骨中选择实际应跟随的部位。

本进阶面板也有已有绑定的局部转移维护，可明确写域、过渡和锁组。不要把已有角色误送进无权重的新绑定入口。

## 6. 人形动作候选

018起，主包已接纳retarget两模块及UI接线：动作来源类型可选`MIXAMO`、`CMU`、`PROFILE`。`MIXAMO`可使用可选骨名映射JSON；`CMU`核对精确预设；`PROFILE`可选择通用来源配置，或选择MMD导入配置并填写明确的动作片段名。面板与`modular_retarget.convert`同核，`profile=`与`mapping=`二选一，不能同时给出；详细签名与示例见`MODULAR-AI-CALLS.md`。

公开UI短入口已有证据：MIXAMO/PROFILE各5源帧、13项通过（preview/stop、旧Action/drivers/source保护），CMU 5源帧→6输出帧、8项通过。这些是短入口，不是完整长片或所有来源。真实人形547帧Mixamo已在722,809点绑定皮肤上完成：121 fcurve/66,187 keys、direction/joint 0°；该路径使用source anatomical frame、逐帧reset和4个既有native roll tweak，upper_arm/thigh roll已修复；spine/spine1全片仍有约32.28°/26.35°透明残余，实际皮肤近景仍须复核。

## 7. 安全改变骨架结构

需要增删尾巴、辅助骨或肢体时，从保留的参考开始，改变组合后创建**新参考候选**，检查并确认，再生成**新rig**。旧角色、旧Mesh、旧Action和人工编辑保持。

新结构不会自动继承旧权重与动画。新参考／新rig会清空工作台中的旧结果与动作指针，但旧对象和Action仍保留在工程里。接下来应重新绑定，或明确选择合法供体和目标转移权重，再重做／重定向受影响动作；核对Mesh的Armature目标以及Action/Slot所属角色。

首版不承诺任意结构变化后权重、动画和手改无损自动迁移。普通比例或关节位置改变也需要重新检查定位、绑定和变形。

## 8. 保存、冷开与回退

把选定候选保存到新的工程文件，保留原始Tripo输出、使用到的资源和作业回执。独立重开后核对对象、Armature目标、控制器、关键姿态、Action/Slot及贴图依赖。

磁盘文件不恢复内存中后台任务的apply权限或临时预览会话；重开后如需重新求解或创建候选，重新准备。源、rig或代理改变时旧结果会拒绝应用，应重新求解而不是修改旧SHA。

回退时保留新工程，使用交付的旧插件包和原工作副本；旧C94角色继续走C94流程。不要用旧版本覆盖仍在编辑的新结构，也不要把Undo当成文件备份。
